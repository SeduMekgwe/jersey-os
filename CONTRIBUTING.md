# Contributing

Jersey OS is proprietary software. Participation requires authorization from Jersey No.10 Collective and does not grant a license beyond the agreed contribution terms.

## Workflow

1. Link work to an approved issue or decision.
2. Keep changes within one module or clearly document cross-module impact.
3. Add or update tests and documentation with behavior changes.
4. Run formatting, build, tests, and contract generation checks locally.
5. Submit a small pull request describing intent, risk, migration, and rollback.

## Standards

- Follow [module boundaries](docs/module-boundaries.md) and existing ADRs.
- Never commit credentials, personal data, tokens, or production exports.
- Use organization scope in authorization and persistence by default.
- Use migrations for schema changes; do not edit applied migrations.
- Preserve backward compatibility or state the rollout plan.
- Record significant, durable decisions as ADRs using the [template](docs/adr/template.md).

## Review checklist

- Domain invariants and authorization are enforced server-side.
- Logs contain correlation context but no secrets or sensitive payloads.
- Retries are idempotent and external side effects are protected.
- Failure behavior, telemetry, and operational recovery are documented.
- Generated artifacts are regenerated by their owning tool, not hand-edited.
